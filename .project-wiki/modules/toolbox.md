# Browser Toolbox And Agent Center

## Purpose

Groups browser-first tools and the portable Toolbox Agent capability center. Files/secrets remain local unless the documented feature needs a CDN, Edge service, or native Agent.

## Main Flow

Compression and OCR use Workers; face masking uses local Canvas; password generation uses browser cryptography; Markdown preview is local. Image compression validates magic bytes and animated containers before decode, inspects EXIF/ICC data, normalizes orientation through the browser image decoder at full resolution, classifies a bounded thumbnail, and evaluates a bounded candidate preview before choosing an output. JPEG XL uses the pinned libjxl decoder because Chromium cannot be assumed to display it natively. UI classification requires both substantial flat area and dense edges so textured photos do not inherit screenshot settings. Quality comparison resizes both references through the same browser path; original fallback messages distinguish insufficient gain and quality rejection, while codec load or encode failures fail the task. A stable job ID owns each result. Workers process one image at a time, are reused to retain lazily loaded codecs, and are terminated for hard cancellation; stale compatibility-decode callbacks are ignored after a slot is replaced. Unknown/low-memory devices, AVIF/JXL work, unknown-size inputs, and images over 24 MP run one job, while capable desktops may run two smaller jobs. Candidates that fail the quality gate are never returned. Auto/keep mode preserves the original when an ICC profile cannot be classified safely. A main-thread decode fallback exists only for browsers without Worker `createImageBitmap` or `OffscreenCanvas`; encoding always stays in the Worker.

Image codecs and support libraries are fixed-version runtime CDN modules rather than package dependencies. The Worker loads JPEGli, libwebp, libavif, libjxl, exifr, libimagequant, and OxiPNG only when a candidate needs them. JPEG output uses a bounded adaptive search for Smart/Higher and a complete preset-specific distance ladder for Smaller, then keeps the smallest candidate that passes the quality gate; these are settings of the same encoder, not codec fallbacks. PNG re-encoding uses a high-quality lossy palette pipeline: libimagequant reduces 24/32-bit pixels to an indexed PNG with at most 256 colors, then OxiPNG optimizes those PNG bytes losslessly. Eligible original PNG bytes can also be optimized directly by OxiPNG without a truecolor PNG encoder. No alternate JPEG encoder is loaded. Batch download loads the same pinned zip.js runtime family as the standalone ZIP tool and stores already-compressed image entries without redundant deflate. See `THIRD_PARTY_NOTICES.md` for versions and licensing. The libimagequant upstream GPL/commercial license is a release gate; the MIT wrapper does not replace it.

Completed image results can be copied directly to the system clipboard. A supported result MIME is written as-is; otherwise the compressed result, including JPEG XL through libjxl, is decoded and copied as PNG so the clipboard never falls back to the original source image.

Text extraction dynamically loads PDF.js when a PDF is selected, shares one document proxy between preview and extraction, reads native page text first, then renders short or empty text-layer pages sequentially and sends them through OCR. Each completed page is published immediately so earlier pages remain browseable and copyable while later pages continue; OCR pages retain their detected regions for the same selectable box overlay used by images, while native text-layer pages do not show boxes. A failed run retains completed pages and retries from the first missing page. Editing and full-document TXT export unlock after the run finishes. The Agent center reports portable protocol-registration results and links to LAN/native acceleration and version control.

The standalone `/toolbox/zip` packer is separate from media compression. Chrome/Edge users select one directory or multiple files, filter a virtualized tri-state tree, choose Smart, Maximum, or Store-only packaging, then optionally customize the compression level (0–9) and whether already-compressed files are stored directly. The archive streams directly to a user-selected file. `zip-packer.ts` owns bounded metadata scanning, suggested exclusions, selection derivation, safe paths, source-change checks, progress, cancellation, and the `zip.js` writer. Default exclusions apply only to directories: those branches keep their handles but defer recursive enumeration and metadata reads until the user expands or selects them. A directory or file that the File System Access API cannot actually read is removed from the pending archive, recorded, and does not stop its readable siblings; the completed ZIP reports those skipped paths. The directory row, apart from its checkbox, also expands or collapses the branch. Selection totals intentionally describe only loaded nodes while deferred branches are present.

## Pay Attention

- Compression selectors use the shared portaled `SelectMenu`: menus escape the tool shell's `overflow-auto` clipping and use the same theme surface as their trigger so explanatory text cannot bleed through. Keep the shell scrolling behavior intact.

- Office compression is the third media-compression tab, after video. It accepts one PPTX/DOCX/XLSX at a time, defaults to smart image compression, and keeps all processing local. Old binary, macro-enabled, encrypted and signed documents are unsupported. Package detection uses the root relationship and main-part content type, not the extension alone. Scan all relationship parts and deduplicate internal image targets; never fetch external targets or recurse into embedded documents. XML is read-only and copied verbatim.
- Office images use the same `compressImage` pipeline and shared defaults as the normal image tool (`keep` format, compatible output, `stripMetadata: false`, white JPEG background). The selected Smart/Smaller/Higher preset controls the same candidate encoders and quality gates; unsupported, animated, undecodable, or quality-rejected images preserve the source, while codec load/encode failures and ZIP extraction/CRC failures abort the document.
- Office compression returns a Blob directly; the result card retains only its URL and size. Image encoding returns replacement bytes or null to preserve the source, with codec fallback handled once in the image adapter. Development builds log the shared image-pipeline diagnostics per Office image, but do not aggregate them or expose them in the production UI. Progress carries only stage and fraction; the panel uses the same rounded brand-color track as video compression, with accessible progress values and reduced-motion support.
- Office reads bounded XML/image parts and streams untouched compressed entries through zip.js pass-through with their original method, CRC and uncompressed size into an in-memory Blob. Extract images sequentially in batches of at most two and always write ZIP entries in their original order. Enable two reusable image Workers only when navigator.deviceMemory reports at least 16 GiB; unavailable reports or values below 16 GiB use one. This API is rounded and capped by the browser, not a measurement of free memory. A batch containing an image with unknown dimensions, more than 24 MP, or a format other than static JPEG/PNG/WebP encodes serially. Drain each batch before preparing the next; never retain all decoded images or replacements. The shared pinned runtime loader lives in `zip-runtime.ts`. Office ZIP operations disable library Workers to avoid other ZIP tools' global `terminateWorkers()` calls; image encoding has its own Workers. The input and output are capped at 2 GiB for the browser memory download path. Abort cancels all active image Workers and the ZIP transfer. If the complete document does not become smaller, return the original file. No output-resolution reduction is allowed. Browser memory failures remain possible on large decoded images.
- Office release validation must include actual PPTX/DOCX/XLSX samples opened in Microsoft Office, plus equality of all unmodified decompressed entries. Source-level boundary tests do not establish Office compatibility or a guaranteed compression ratio. Do not claim pixel-identical JPEG output from thumbnail quality metrics. The user reports successful compression of their Office samples; this does not assert coverage of every document feature.

- Keep the image UI split into panel, options, results, comparison, and job controller. Reuse `DialogModal` and `SelectMenu`; synchronized comparison remains image-tool-specific, and byte formatting is shared locally in `image-format.ts`. Completed-result savings stay beside the filename so the lower metadata row remains scannable. Only the active image tab listens for pasted files.
- Job updates synchronously update the controller ref before React rendering so immediate queue pumping sees current state. Preserve source dimensions across retries; result dimensions belong to the result. Release pending ingestion URLs on unmount and reset terminated Worker slots. Keep only rejection metrics, not rejected encoded buffers or full-resolution quantization previews, after candidate evaluation.
- Comparison labels match original-left/result-right, with both layers sharing the same fitted aspect ratio. The comparison dialog uses the full viewport work area, fits the image to its available width and height without upscaling past its source dimensions, and keeps wheel zoom deliberately fine-grained. Its 1:1 button maps one output pixel to one CSS pixel. Candidates that cannot be evaluated must not receive fabricated perfect metrics; original fallback still follows the normal metadata/dimension rules.

- PNG color safety is decided from real chunks before EXIF fallback: a valid `sRGB` chunk is safe, `iCCP` is bounded-inflated and classified from ICC structure/tags, and standard `gAMA`/`cHRM` values are recognized. Known Display P3, Adobe RGB, ProPhoto, and other clearly wider matrices remain protected; only genuinely unclassified ICC profiles use the uncertain-color fallback.
- JPEGli photographic/mixed distance ladders are Higher `1/2.5/4/6`, Smart `1.5/3.5/6/9`, and Smaller `2.5/5.5/9/13`, using 4:2:0 chroma. UI text and flat illustrations use the more conservative Higher `0.6/1.5/2.5/4`, Smart `1/2.5/4/6`, and Smaller `1.5/3/5/7` ladders with 4:4:4 chroma. Smaller evaluates every rung. Smart/Higher start at the second rung and attempt at most one follow-up: the first rung after quality rejection, or the third rung when the first result saves at least 20% and has quality headroom. Otherwise stop. Keep the smallest passing candidate; a failed follow-up gate never discards the previous passing result. `src/lib/image-compress/search.ts` owns adaptive decisions.
- PNG re-encoding uses libimagequant followed by OxiPNG, including for gradients and complex transparency; thumbnail heuristics must not skip it. Smart starts at 256 colors and quality 80; it tries 128 colors once only when the first result saves at least 20% and has quality headroom. Higher uses one 256-color target. Quantizer minimum quality is zero so rejection is handled by the shared visual gate instead of a codec exception, while Smaller searches 128/64/32/16 colors and also 8/4 for UI text, icons, and flat illustrations. Smaller targets quality 45–55, uses zero dithering for graphic classes, low paired dithering for mixed/photos, and stronger paired dithering only for gradients. Every palette result passes the quality gate and the smallest passing byte result wins; Smaller evaluates its full palette list. Smaller accepts SSIM 0.960, edge error 0.100 (0.075 for text), and alpha MAE 0.015. For an eligible original PNG, Smart/Higher run direct source-byte OxiPNG optimization if no candidate saves at least 20%; Smaller always compares this lossless candidate. Use level 2 (4 for Smaller), with transparent-RGB optimization disabled. This is only allowed when dimensions and metadata intent permit original retention; never reuse source bytes for metadata removal or conversion to another format. If neither path provides meaningful savings, preserve the original. Codec failures remain errors. Adaptive headroom requires SSIM >= 0.993 (0.997 for Higher), edge error <= 0.0175 for text or 0.0275 otherwise, and alpha MAE <= 0.5/255. These are initial policy thresholds, not benchmark-derived guarantees.

- Video compression is Chromium desktop-first and must stream reads/writes; do not switch to whole-file buffers/Blobs/WASM filesystem.
- Image compression accepts static JPEG, PNG, WebP, AVIF, and JPEG XL after content sniffing. Keep HEIC/HEIF, GIF/APNG/animated WebP, and SVG out of this raster pipeline. Never silently keep only the first animation frame.
- Keep remote image-codec imports pinned and conditional. Do not add the codec packages to `package.json`, import them statically, use floating CDN versions, or load AVIF/JXL/imagequant during route startup. JPEG must use JPEGli, and PNG must use libimagequant followed by OxiPNG; a codec failure must not invoke an alternate encoder.
- Preserve the distinction between optional compression and mandatory user intent. Original-file fallback is allowed for keep/auto mode and PNG-to-PNG output when dimensions and requested metadata behavior are unchanged. Explicit conversion or metadata removal may legitimately produce a larger file and must say so. Metadata-removal help names capture time, device, and location information and notes possible output growth instead of describing fallback internals.
- Treat orientation and color as pixel semantics, not disposable metadata. Browser decode applies orientation once. Auto/keep mode preserves unmodified wide-gamut images unless the user explicitly requests conversion or metadata removal.
- Keep image-compression UI copy focused on controls and results; omit format-rejection explanations, candidate-strategy filler, aggregate source-size/CDN hints, task-isolation captions, and inline licensing prose. Image compression never reduces output resolution: both Worker and main-thread decoding use full-size pixels. Small classification/quality previews do not affect exported dimensions. Device memory only controls candidate selection and concurrency; oversized images may fail rather than being silently downscaled. The options grid uses two columns normally and three when auto strategy is shown.
- libimagequant is GPL-3.0-or-later/commercial despite its wrapper being MIT. Keep licensing details in `THIRD_PARTY_NOTICES.md`; do not ship a production deployment under an incompatible licensing assumption.
- The image comparison view must keep both layers in one transform and pixel coordinate system. Do not return to independent side-by-side zoom states.
- Keep the standalone `/toolbox/zip` packer separate from media compression. Image compression has only a narrow result-archive adapter in `src/lib/image-compress/image-archive.ts`; do not reuse the directory scanner or expand that adapter into a second general ZIP tool. The standalone packer intentionally targets secure-context desktop Chrome/Edge and requires native directory/save pickers; do not add Blob, StreamSaver, password, resume, or alternate archive engines without a confirmed scope change.
- ZIP entries are written sequentially to keep memory and state bounded. The pinned CDN module `@zip.js/zip.js@2.8.59/index-native.min.js` preloads after the initial scan, supplies incremental `BlobReader` input and the codec Worker, and must stay outside the application bundle. It requires access to `cdn.jsdelivr.net`, but selected file contents are never uploaded; pass the native `createWritable()` stream directly to zip.js. Do not introduce entry parallelism without OPFS-backed temporary streams and benchmark evidence.
- Keep `BlobReader(file)` and the Smart preset at level 6. Directory metadata progress is throttled, while selection state and selected-file totals are derived together; ZIP entry IDs are computed only when writing starts.
- Never use a path-length threshold for ZIP exclusions. Preserve `AbortError`, output-stream failures, compression failures, and source-change checks as task failures; only per-entry File System Access read failures are automatically skipped.
- Keep the ZIP UI surface intentionally small: only compression level and the skip-already-compressed policy are adjustable. ZIP64, Workers, streaming, metadata, encryption, split archives, and custom codecs remain automatic or out of scope.
- OCR/model resources load only on explicit recognition. Keep external-WASM ONNX alias; default bundle exceeds Netlify file limits.
- Keep PDF.js lazy and browser-only. Its core is a split client chunk, while the version-matched Worker, CMaps, standard fonts, and WASM load from the pinned jsDelivr package path. Process extraction pages sequentially; the comparison viewer may retain only its current rendered Canvas and must cancel superseded page renders.
- Face/OCR/password data stays browser-local. Clipboard and File System Access require user gestures.
- Password wordlists are fetched lazily and integrity-checked; offline modes must still work if fetch fails.
- Agent center is not proof of a resident process. Native callback ownership stays with LAN/version-control routes.
- Shared image preview behavior is used by articles, LAN, OCR, and repository view; keep it consistent.
