按“继续使用 CDN”这个前提重新检查后，我认为当前 ZIP 实现没有看到会必然导致 ZIP 损坏的核心错误，但有 2 个实际逻辑风险和 5 个比较明确的性能优化点。优先级如下。 1. 需要修：默认排除规则会误伤同名普通文件 现在是： ```ts const suggestedExcluded = inheritedExclude || DEFAULT_EXCLUDES.has(name) ``` 而 `DEFAULT_EXCLUDES` 里有： ```text .git node_modules dist build target .idea ... ``` 判断没有检查 `child.kind`。因此如果项目里存在一个普通文件： ```text build target dist ``` 它也会被默认取消勾选。比如 Unix 项目里名为 `build` 的构建脚本完全可能存在。 建议改成只自动排除目录： ```ts const suggestedExcluded = inheritedExclude || (child.kind === 'directory' && DEFAULT_EXCLUDES.has(name)) ``` 这个属于真正的逻辑问题，我建议优先修。 2. 最大性能问题：明明排除了 node_modules，扫描时仍然把它全部扫完 当前流程实际是： ```text 选择项目 ↓ 遍历 src ↓ 遍历 node_modules ↓ 遍历 .git ↓ 遍历 target ↓ 建立全部节点 ↓ 再对所有文件 getFile() ↓ 读取 size / lastModified ``` 也就是说，“建议排除”目前只影响最终 checkbox，并不影响扫描。 假设： ```text 项目本身 2,000 files node_modules 80,000 files .git 15,000 files ``` 用户实际上只想压 2,000 个文件，但网页还是会处理接近 100,000 个文件。 这很可能是当前最大的真实性能瓶颈，甚至比 DEFLATE 本身更明显。 最好的方案是做“lazy excluded directory”： ```text node_modules 已建议排除 · 尚未展开扫描 用户勾选/展开 ↓ 此时才扫描内部 ``` 也就是默认排除目录先只保存： ```ts { name: 'node_modules', kind: 'directory', suggestedExcluded: true, loaded: false } ``` 不进去递归。 这会让典型 Web 项目的“选择目录 → 出现文件树”速度提升非常明显。 3. 扫描阶段存在 React 更新风暴 这里： ```ts onProgress(filesRead, bytesRead) ``` 基本上每完成一个 `getFile()` 都回调一次。 然后 UI： ```ts setScanProgress({ files, bytes }) ``` 所以 100,000 文件理论上可能触发接近 100,000 次 state update。 压缩阶段反而做对了，你已经有： ```ts if (!force && now - lastUpdate < 120) return ``` 也就是最多约 8 次/s 更新 UI。 扫描阶段应该采用同样策略，例如 80~120ms 更新一次。 这个修改很小，但对于数万文件目录非常值得。 4. Checkbox 每点一次，目前会完整遍历文件树大约 3 次 现在 `selected` 一变化，会触发： ```ts deriveZipSelection(scan.nodes, selected) ``` 完整 O(N)。 然后： ```ts selectedZipEntries(scan.nodes, selectionStates) ``` 又 O(N)。 再然后： ```ts zipSelectionStats(scan.nodes, selected) ``` 又 O(N)。 所以一次勾选大致： ```text 100,000 nodes derive states → 100,000 selected entries → 100,000 stats → 100,000 ≈ 300,000 次节点处理 ``` 虚拟列表只能解决 DOM 数量，解决不了这里的 JS CPU。 最低成本的优化是先把： ```ts selectedEntryIds ``` 从 `useMemo` 删除。 因为它实际上只有“点击开始压缩”的时候才需要。 直接在： ```ts startWriting() ``` 内部计算： ```ts const selectedEntryIds = selectedZipEntries(scan.nodes, selectionStates) ``` 这样普通 checkbox 操作立刻少一次全树遍历。 第二步再考虑把： ```text deriveZipSelection zipSelectionStats ``` 合并成一次 traversal。 这样从： ```text 3N ``` 先降到： ```text 1N ``` 已经足够明显。 5.
