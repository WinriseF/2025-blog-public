这个站现在就是一坨。

最开始只是想找个地方放文章和项目，后来写着写着，日历、音乐、图片、小游戏、新闻和各种工具也都塞了进来。现在再叫它博客多少有点不准确，但我也没想好更合适的名字，所以还是先这样。

简单来说，这里放的基本都是我做过的、正在做的，或者某天突然想做的东西。

## 这里有什么

文章还是会继续写，主要是项目复盘、开发记录、踩坑过程和一些阶段性的学习笔记。

我不太想只放最后那个看起来还不错的结果。很多时候，中间为什么这么改、哪里做错了、最后为什么放弃原来的方案，反而更值得记下来。

项目页也不是严格意义上的开源项目列表。有些项目会放 GitHub，有些因为比赛、数据或者隐私问题不会公开源码，只会写一篇文章讲讲做了什么。还有一些项目可能早就不维护了，但只要当时确实折腾过，我觉得就还有记录的价值。

除此之外，还有一个越来越大的 Toolbox。

一开始只是放几个简单的小工具，后来慢慢有了图片压缩、人脸打码、文本提取、Markdown 预览、密码生成、文件传输、Git / SVN 查看和 Codex Session 解析。

这些东西之间不一定有什么关系。很多时候只是因为我自己刚好需要，又不想临时找一个不知道会不会上传文件的网站，于是干脆自己写一个。

能直接在浏览器里做的功能，基本都会尽量留在浏览器本地。需要网络、系统权限或者原生能力的部分，再交给单独的服务或者 Toolbox Agent 处理。

## 这个站为什么越来越复杂

因为我一直在往里面加东西。

它一开始真的只是几个页面，现在已经分散在多个仓库里。文章、图片、站点本体、原生 Agent 和其他工具各管一部分，部署也同时用了 Vercel、Netlify、EdgeOne 和 Supabase。

这不是一开始设计好的宏大架构，单纯是功能长到哪里，就把哪里拆出来。

好处是每一块相对独立。某个工具坏了通常只会坏它自己，实在修不好也可以直接拆掉，不至于把整个站一起带走。

坏处也很明显：仓库越来越多，部署配置越来越长，有时候隔一段时间回来，我也得先看看架构文档，才能想起来当初为什么要这么写。

不过个人项目有一个好处，就是不用假装第一次设计就是正确的。不好维护了就合并，边界不清楚了就重写，确实没用了就删掉。

## 关于本站

站点本体主要使用 Next.js、React 和 Tailwind CSS。

文章和大部分展示内容仍然是仓库里的 Markdown、JSON 和图片文件，没有 CMS，也没有后台管理页面。要改内容就直接改文件，然后正常提交。

虽然我自己有服务器，但这个站没有全部放在一台服务器上。实际用下来，静态页面、图片、边缘函数和实时通信适合放在不同的平台，国内外访问也会更稳定一点。

这个方案肯定算不上简单，但目前还能维护，也确实解决了一些问题，所以暂时继续这么跑。

以后功能大概还会增加，也可能会删掉一批。这个站没有什么确定的最终版本，它基本就是跟着我最近在做什么一起变化。

## 一点说明

文章里的内容大多来自我自己的学习、开发和比赛经历。

有些判断现在看可能已经不对了，有些方案也可能早就过时。如果你看到了问题，可以把它当成我在某个时间点留下的记录，而不是标准答案。
